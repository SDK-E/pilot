# Connector spec compliance audit

Status: audit only, 2026-09-17. No behavior changed by this document.

**Update, same day**: the architecture this audit describes (8 hardcoded
providers/adapters, `connector_connections`) was replaced by
[ADR-0023](./0023-dynamic-connectors.md) — one generic OAuth2 + REST engine
driven by admin-configurable `connector_definitions` rows. File paths and
some "Gap" rows below (§10 pagination, §25 multi-account, §2/34/43
identity/versioning) now read differently against the new system; treat
this document as a historical snapshot of the ADR-0021 architecture, and
ADR-0023 as the current state.

**Update, 2026-09-18**: re-verified §10, §25, §26/27, §40, and §2/34/43
against the current engine (`base-connector.ts`,
`adapters/base-connector-adapter.ts`, `dispatch-custom-connector.ts`,
`connector-definitions.ts`, pilot-ai's `connector.ts`). Rows updated below;
see each row's Evidence for the current-file citation. A small test-coverage
gap in §10 was closed in this pass (`tests/unit/base-connector-adapter.test.ts`,
"a nextCursorPath is extracted and round-trips back into the next call's
params"); everything else confirmed either still holds as originally
written or is corrected in place, with no architectural work done.

**Update, 2026-09-18 (later same day)**: §10 is now closed, not partial.
This pass fixed the two admin/data gaps the entry above still listed: (1)
`ConnectorDefinitionAction.nextCursorPath`'s JSDoc
(`db/schema/connector-definitions.ts:40-46`) now names the convention — a
fixed `{cursor}` placeholder every paginated action's `urlTemplate` (and
`bodyTemplate`) can use, substituted from the caller's `params.cursor` on
the next call, chosen because pilot-ai's `connector` tool already accepts
free-form `params: z.record(z.string(), z.unknown())`
(`pilot-ai/src/mastra/tools/connectors/connector.ts:42`), so `cursor` is
just another key the model already knows how to pass, no schema change
needed; (2) Slack's seeded `list-channels` action
(`connector-seed-definitions.ts:66-76`) now sets
`nextCursorPath: "response_metadata.next_cursor"` and a `{cursor}`
placeholder in `urlTemplate`, matching Slack's real `conversations.list`
cursor convention exactly — the first seeded connector action to actually
exercise pagination. Fixing this also surfaced and closed two bugs: (a)
`substitute()` (`adapters/base-connector-adapter.ts:20-31`) used to leave
an unresolved `{cursor}` placeholder literally in the URL on a first call
with no cursor yet; it now substitutes an absent/null param as `""`,
matching Slack's own documented default for `cursor`; (b) pilot-ai's
`connectorToModelOutput`/`itemsToText`
(`pilot-ai/src/mastra/tools/connectors/connector.ts:87-118`) parsed
`nextCursor` into its output schema but never mentioned it in the text
handed to the model, so an agent had no way to discover a cursor existed —
`itemsToText` now appends a "call again with params.cursor set to ..."
line when `nextCursor` is present. The full round trip (Slack's exact
shape: first call extracts `response_metadata.next_cursor`, second call's
`cursor={cursor}` substitutes it back in) is proven by
`tests/unit/base-connector-adapter.test.ts`, "Slack's seeded list-channels
action round-trips response_metadata.next_cursor into the next call's
cursor param".

## Purpose

A 48-section generic "Connector Behavior & Agent Interaction Specification"
was used as a rubric to review Pilot's existing connector system
([ADR-0021](./0021-connectors.md)). This is the section-by-section result:
current status, the file that proves it, and which phase of the approved
roadmap (`docs/decisions/0022a-connector-spec-audit` is this doc; the phase
plan itself lives outside the repo in the planning session, summarized in
Phase map below) closes each gap. Resume connector work by reading this
table, not by re-deriving scope from the original spec text.

Status legend: **Met** — already satisfies the section as written. **Partial**
— satisfies part of the section, a concrete gap remains. **Gap** — not
implemented today.

## Net gaps, in priority order

1. **§18/19/20/46 — error taxonomy.** The single highest-leverage fix: one
   generic 502 today hides auth-required, not-found, rate-limited, and
   provider-down behind the same string. Closed by Phase 2.
2. **§10 — pagination (closed 2026-09-18).** No longer a gap. The cursor
   param-name convention is fixed and documented (`{cursor}` placeholder /
   `params.cursor`, `db/schema/connector-definitions.ts:40-46`), a real
   seeded action exercises it end to end (Slack's `list-channels`,
   `connector-seed-definitions.ts:66-76`, using Slack's actual
   `response_metadata.next_cursor` shape), the model can now see the
   returned cursor in the tool's text output (`connector.ts`'s
   `itemsToText`, previously silently dropped), and the round trip is
   test-covered (`tests/unit/base-connector-adapter.test.ts`, "Slack's
   seeded list-channels action round-trips response_metadata.next_cursor
   into the next call's cursor param").
3. **§9 — resource identity consistency**, specifically Gmail's thin search
   result. This referred to the retired per-provider Gmail adapter
   (ADR-0021); re-verify against the current dynamic engine separately if
   still relevant — out of scope for this pass.
4. **§25 — multi-account selection (updated 2026-09-18).** Not a gap:
   ADR-0023 explicitly settled connectors as org-wide/single-connection-per-
   slug and names multi-account as intentionally deferred, not a TODO to
   close. Nothing to build here without a connection-scope redesign the
   product hasn't asked for.
5. **§26/27 — files as first-class resources (confirmed 2026-09-18).** The
   dynamic engine is JSON-only end to end today — no binary/blob result,
